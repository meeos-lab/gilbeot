### 10-1. 신호와 사건 창
| 근거 | 조건 | 점수 | 출처 |
|---|---|---|---|
| HARD_BRAKE | 1 s 안 Δv ≥ 3 m/s(18 km/h↑) + 다음 1 s 낮음 | 1 | 차(1 Hz) |
| SWERVE | 40 km/h↑, 1 s 안 60°↑, 브레이크 없이 | 1 | 차 |
| **IMPACT** | 10 Hz 표본, 두 표본 사이 감속률 ≥ 14 m/s² 이고 Δv ≥ 2.2 m/s, 0.08~0.5 s, 그 뒤 0.5 s 동안 사건 전 50 % 아래. 즉시 전송 + 표본 20개, 허브 재검증 | 3 | 차 |
| STOP | 사건 300 m 안 5 km/h 미만 30 s. 휴게소 500 m 안 제외 | 2 | 허브 |
| AIRBAG | 사건 뒤 30 s 동안 1 Hz 읽기(운전석·조수석). 에뮬레이터 미지원 → 훅 | 3 | 차 |
| COMM_LOSS | IMPACT 있는 차, 사건 뒤 15 s 안 마지막 보고, 8 s↑ 무응답, 터널+500 m 밖 | 2 | 허브 |
| NO_RESPONSE | IMPACT/AIRBAG 뒤 "괜찮으세요?" 10 s + 카운트다운 20 s 무응답. "괜찮아요"(버튼·음성)면 창 닫힘 | 2 | 차→허브 `respond` |
- 창: 첫 근거부터 60 s·300 m. 같은 차의 근거는 한 창에 더한다.
- 보정: 사고 다발 구역 안 또는 위험성 '높음' → 문턱 −1(합쳐 최대 −1).

### 10-2. 판단·확정·단계·해제
- 사고 의심 = 점수 ≥ 3 이고 {STOP, IMPACT, AIRBAG, COMM_LOSS} 하나 이상 → 그 차가 INCIDENT 보고(300 m 병합, 확인 차 수 누적).
- 확정(말하기) = 그룹 차 1대 | 모르는 차 2대 | 모르는 차 1대: 점수 ≥ 6 이고 {NO_RESPONSE, AIRBAG} 하나 이상(또는 IMPACT+COMM_LOSS 이고 끊기기 전 v ≤ 5 km/h) 이고 세션 ≥ 120 s 이고 타당성 위반 < 3 이고 30 분 안 강한 확정 0.
- 단계 2 = 점수 ≥ 6 | 확인 ≥ 3 | 공식 확인. 2단계만 한 번 더 말한다(소리 규칙).
- 해제 = 보고 차 60 km/h↑ | 3대↑ 60 km/h↑ 통과 + 2 분 정차 0 | 공식 `endTime`. 1~2대 통과 = partial. 만료 15 분, 1 km 안 정체 칸 있으면 정체 끝까지(최대 2 h).
- 공식 확인 = 순정 내비 `TrafficStatus.trafficEventList` ACCIDENT/ROAD_DAMAGE/DISASTER(차가 올림) ±2 km, 또는 PC 허브의 도로공사 문자·VMS. 같은 지점·시간의 내비 경보와는 한 번만.
- 타당성(ETSI TR 103 460 표 3): 속도 ≤ 70 m/s, |가·감속| ≤ 12 m/s²(IMPACT 이벤트 제외), 연속 보고 |Δs − v̄Δt| ≤ 50 m + 0.1 v̄Δt, 정지면 위치 불변, 간격 0.5~5 s. 위반 3/10 분 → 확인 수 제외·강한 확정 불가, 10 → 세션 종료.

> 고칠 것: ① 속도 표본이 흔들리면(ABS 작동 중 바퀴 속도) 최대 제동을 충돌로 볼 수 있다 — 실차 `PERF_VEHICLE_SPEED` 의 잡음을 재야 한다. ② "0.5초 안에 사건 전 속도의 절반 아래" 조건 때문에 충돌 뒤 굴러가는 약한 충돌은 IMPACT 로 못 잡고, 급제동+정차(3점)로 30초 뒤에야 사고 의심이 된다. 평균내기·문턱 18·최소 간격 0.2 s·유지 75 % 를 모의실험으로 견줘 봤으나(`impact_variants`) 잡음 오탐과 누락 오탐이 서로 맞바뀌어 속도만으로 깔끔히 가르는 안이 없었다 — 가속도(IMU) 신호나 실차 잡음 측정이 필요하다. 오탐은 "괜찮으세요?"에 '괜찮아요'로 거둘 수 있다.

|---|---|---|---|
| 5판: 200 ms 안 Δv ≥ 3.0 + 0.5 s 유지 | 0 % | 100 % / **0 %** / — | 0 % |
| **6판: 감속률 ≥ 14 m/s²(1.43 g), Δv ≥ 2.2(8 km/h), 0.08 ≤ Δt ≤ 0.5 s, 0.5 s 유지(사건 전 50 % 아래)** | 0 %(누락 50 %에서도) | 100 % / 97~99 % / 80~86 % | 0 % |

- 5판 규칙은 표본이 빠지면 200 ms 창에 짝이 없어 충돌을 통째로 놓쳤다(사고 순간 센서·IPC 지연은 흔하다). 6판은 **평균 감속률**로 보아 창이 0.5초까지 늘어나도 제동(최대 1.1 g = 10.8 m/s²)과 30 % 여유를 두고 갈린다. 감속률 문턱 12·14·16 모두 오탐 0 — 14 를 택한다.
- 저속 추돌(8→0 m/s, Δv 8 km/h = EDR 경계)도 100 % — 주차장·정체 꼬리 추돌이 잡힌다는 뜻이라 **정차 중(v < 1 m/s)에서 받히는 것(Δv 양수)은 여전히 못 본다**(한계 §10-2 유지).
- 표본 누락 50 %에서 검출이 80 %대로 떨어진다 → 차 쪽은 10 Hz 콜백 손실을 로그로 세고, 손실이 30 %를 넘으면 "충돌 감지 저하"를 개발 패널에 표시한다(제품은 VHAL 품질 문제로 보고).
- 허브 재검증은 같은 규칙으로 표본 20개를 다시 계산한다(차·허브가 같은 함수, 대조 검사 항목).

## 1. 원칙
- **단정하지 않는다.** 끝까지 "사고 의심"이고 근거를 그대로 읽는다. 공식 정보(도로공사)가 있을 때만 "사고"로 올린다.
- **차는 신호, 허브는 판단.** 여러 차·시간·거리·공식 정보를 모으는 일은 허브(`link_server.py` = `LinkHub.kt`, 대조 검사)가 한다. 통신 끊김은 허브만 안다.
- **읽을 수 있는 것만.** 비상등·타이어 공기압·rpm·가속 페달은 서드파티가 못 읽는다 — 설계에서 뺀다(§7).
- **사람을 끼운다.** 혼자 강한 근거는 운전자 응답 확인으로 보강한다. 사고 난 차에는 먼저 사람부터(대피 안내).
- **소리는 예산 안에서.** 5분에 비상급(사고 의심 2단계·긴급차량) 외 2건까지. 메시지는 '전방 거리 + 무엇 + 누가 확인 + 행동' 한 문장(NHTSA DVI 지침: 짧게, 행동 하나).

| **공식 정보** | ① 차: 순정 내비 `NaviHelper` `TrafficStatus.trafficEventList`(`ACCIDENT` 등, 위경도·시작·끝·설명) → 허브 `/api/road/official` ② 허브(PC): 한국도로공사 실시간 문자·VMS API | 사고 지점 ±2 km 안에 `ACCIDENT` 가 있으면 등급을 **"공식 확인"**(내비/도로공사)으로 올리고 해제(`endTime`)도 따른다. 같은 위치·시간의 내비 자체 경보와는 한 번만 | ✅ ①은 SDK 에 있음(경로 안내 중 제공, 에뮬레이터 실측 필요), ②는 인증키 |

**감지 한계(적어 둔다)**: 측면 충돌·뒤에서 받힌 정차 차는 종방향 속도 변화가 작아 `IMPACT` 로 안 잡힌다(EDR 은 횡방향 Δv 도 본다 — 우리는 없다). 에어백·무응답·다른 차 확인으로 보완. 위치는 차속 적분이라 100 m 단위 오차 — 실차는 내비 위치(NaviHelper)를 쓴다.

## 3. 판단식 — 한 차, 한 지점, 60초

| 근거 | 점수 | 메모 |
|---|---|---|
| 급제동 | 1 | |
| 급조향 | 1 | |
| 충돌(EDR 조건) | 3 | 1판 2 → 3: 제동으로는 못 내는 값이라 그 자체로 강하다 |
| 정차 30초 | 2 | 고속도로 본선 정차는 비정상 |
| 에어백 전개 | 3 | |
| 통신 끊김(충돌 뒤) | 2 | |
| 운전자 무응답 20초 | 2 | "괜찮아요" 응답이면 창을 닫는다 |

- **사고 의심 = 3점 이상** 이고 {정차, 충돌, 에어백, 통신 끊김} 하나 이상. 급제동+급조향(2)만으로는 각각의 위험으로 남는다.
- 기존 규칙 호환: 급제동(1)+정차(2)=3. 지금 시연은 그대로.
- **확정(말하기)**: 그룹 차 1대 또는 모르는 차 2대(지금 규칙). **모르는 차 1대 확정은 6점 이상 + 무응답 또는 에어백 포함 + 세션 2분↑·속도 이력 연속·30분에 1번**. 예: 충돌(3)+무응답(2)+정차(2)=7 ✅, 충돌(3)+통신 끊김(2)=5 ❌(2대 필요 — 끊긴 차는 응답도 못 하니, 이 경우만 "충돌 + 끊김 + 끊기기 전 1초 속도 ≤ 5 km/h" 면 6점으로 본다).
- **단계**: 1단계 3~5점 또는 확인 1대 / **2단계 6점↑ 또는 확인 3대↑ 또는 도로공사 확인**. 2단계만 한 번 더 말한다.
- **문턱 보정**: 사고 다발 구역 −1, 사고 위험성(§6) '높음' −1(합쳐서 최대 −1).
- **해제**: 보고 차 60 km/h↑ 주행, 또는 3대↑ 60 km/h↑ 통과 + 2분간 300 m 안 정차 없음, 또는 공식 정보 해제(`endTime`). 1대만 통과하면 "부분 통행 가능"으로 낮춘다(문장: "…일부 차로 통행 중"). **만료 15분이되, 지점 1 km 안에 정체 칸(앞길 미리보기)이 남아 있으면 정체가 풀릴 때까지(최대 2시간)** — 2차 사고 위험은 대기열이 있는 동안 이어진다.

예
| 상황 | 점수 | 판단 |
|---|---|---|
| 급제동 → 30초 정차(지금 시연) | 1+2=3 | 1단계, 2대 또는 그룹 차 |
| 급조향 → 급제동 → 정차 | 1+1+2=4 | 1단계 |
| 충돌 → 통신 끊김(끊기기 전 정지) | 1+3+2=6 | 2단계, 1대 확정 |
| 충돌 → 20초 무응답 → 정차 | 1+3+2+2=8 | 2단계, 1대 확정 |
| 충돌 → "괜찮아요" | 창 닫힘 | 급제동 위험만 |
| 휴게소 500 m 안 정차 | 0 | 제외 |
| 터널 앞 급제동 → 끊김 | 1 | 끊김 제외, 급제동만 |

## 4. 말하기 — "교통 막힘 주의"와 표준 용어
- 1단계: **"전방 2.6km 사고 의심 구간. 차량 2대 급제동 후 정차 확인. 교통 막힘 주의, 감속 후 차로를 확인하세요."**
- 2단계: **"전방 2.6km 사고 의심 구간. 차량 1대 충돌 후 정차, 응답 없음 확인. 교통 막힘 주의, 서행하세요."** / 도로공사 확인: "전방 2.6km 사고 구간(도로공사 확인). …"
- 근거 구절 순서: 급조향 → 급제동 → 충돌 → 정차 → 에어백 전개 → 통신 끊김 → 응답 없음. 둘까지만 읽는다(길면 행동이 묻힌다).
- 부분 통행: "…일부 차로 통행 중. 서행하세요."
- **표준 대응**(ETSI DENM 원인 코드로 적어 두면 C-ITS 와 이어 붙일 수 있다): 사고 의심 = `accident(2)`, 교통 막힘 주의 = `dangerousEndOfQueue(27)`, 정체 = `trafficCondition(1)`, 긴급차량 = `emergencyVehicleApproaching`. 급제동 전파는 SAE/ISO 의 EEBL 에 해당. 앱 내부 종류 이름은 그대로 두고 대응표만 둔다.
- **권장 속도 연동**: 확정 사고 의심이 앞 1~3.5 km, 정체 칸 없음 → "전방 2.6km 사고 의심. 지금부터 시속 60까지 서서히 줄이세요."(정체 권장 속도와 같은 틀).
- 앞길 스트립 라벨 "사고 의심 · 교통 막힘 주의"(2단계 빨강), 지도 핀 라벨에 "(강함)"/"(도로공사 확인)". 휴대폰 참가자(가족) 화면에도 같은 줄.

## 5. 사고 난 차에게 — 2차 사고 예방 모드 (새 항목)
충돌·에어백·무응답이 내 차에서 생기면 뒷차 전파와 **동시에** 내 화면이 바뀐다.
1. "괜찮으세요?" 큰 버튼 둘([괜찮아요] / [도움 필요]) + 20초 카운트다운(음성도). 무응답·[도움 필요] → 2단계 전파 + 응급 카드(이미 있는 응급 브리핑 기능)로 넘어간다: 위치·차량·탑승 인원 카드 + **[119 전화 화면]** 한 번.
2. 비트박스 안내(도로공사 행동요령) 한 줄씩: "비상등을 켜세요 → 가능하면 갓길로 → 트렁크를 여세요 → 가드레일 밖으로 대피 → 112·119·도로공사 1588-2504". 주행 규제와 무관(차는 서 있다).
3. 가족 그룹이 있으면 그룹 화면에 "아빠 차 사고 의심 — 응답 없음"과 위치. 보호자 휴대폰 알림.
4. 블루링크 ACN(에어백 → 센터 통보)과의 관계를 화면에 숨기지 않는다: "차량 긴급 통보가 있으면 그쪽이 우선입니다" — 우리는 뒷차와 가족에게 알리고 대피를 돕는다.

### 5-1. 기존 서비스와의 자리 (겹치는 곳·우리 몫)
| 서비스 | 하는 일 | 감지 | 알리는 대상 | 걸리는 시간 | 우리와 다른 점 |
|---|---|---|---|---|---|
| **현대 블루링크 ACN** | 에어백 전개 → 긴급 구난 센터 통보, 상담원 연결, 비상 연락처 문자 | 에어백 | 센터·보호자 | 분 단위(상담원) | 뒷차에 알리지 않는다. 사양 적용 차·가입자만 |

| Tago 도로 링크(이 설계) | 위 셋의 사이: 차 신호 → 허브 판단 → 뒷차·가족·사고 차 | 차속 10 Hz·조향·(에어백)·보고 간격 | 뒤 10 km Tago 차, 그룹, 사고 차 자신 | 초 단위 | 공식 확인은 느리지만 정확, 우리는 빠르지만 '의심' — 둘을 잇는 것이 설계의 핵심(§8 교차 확인) |

시연에서 보일 한 장면: 앞차 충돌 → **3초 안**에 뒷차 "사고 의심 · 교통 막힘 주의" → (가정) 수 분 뒤 도로공사 문자 → "사고 구간(도로공사 확인)". 발표에서는 교통안전이음을 숨기지 말고 "거기에 차량 신호와 차대차 속도를 더한 것"으로 말한다.

## 6. 사고 위험성(예측) — 지금 이 차·이 길·이 날씨

### 6-1. 입력(읽을 수 있는 것만)
비(내 와이퍼 + 앞차 2대↑ 와이퍼) · 외기 온도(표준 `ENV_OUTSIDE_TEMPERATURE` ✅ 실측 25 °C, VC 조절 없음 → 훅 `temp_sim`) · 브레이크 페달 ✅ · 핸들 각 ✅ · 크루즈 상태 ✅ · 연속 운전 시간(Odometer trip time ✅) · 앞 10 km 위험(링크) · 사고 다발·결빙 다발 구역(§8) · 야간·터널·교량(경로 파일) · 제한속도(경로 파일, 시연 100).
못 읽는 것: 타이어 공기압(Pleos 비공개 권한, 저압 기준값 137 kPa 만 공개) · rpm(API 없음) · 가속 페달(공개 API 없음 → 속도 변화로 대신) · 비상등. 실차 승인 뒤 자리만 둔다.

## 7. 못 읽는 입력과 그 자리
타이어 공기압·TPMS 경고(PRIVATE_CAR_SAFETY) · rpm · 가속 페달 · 비상등. 설계에는 "승인 뒤 붙는 자리"(점수 항목 주석)만 두고, 표준 API 권한 신청은 하지 않는다(Vehicle 권한은 앱 마켓 사전 승인분만 선언 가능 — 미승인 선언은 심사 탈락).

"고속도로 도로위험도지수(5분)"는 확인되지 않아 뺀다.
- **경로 파일**: `gyeongbu_route.json` 에 `zones: [{kind: accident|icing|tunnel|bridge, s0, s1, name, count, year, source}]` — 좌표를 경로에 투영해 s 로 바꾼다. 터널·교량은 **OSM 의 `tunnel=yes`·`bridge=yes` 태그**를 `fetch_highway_osm.py` 에서 같이 받아 구간으로 만든다(지금 파일에는 없다 — 데이터 과제). 시연값은 `source: "demo"` 로 표시하고 README 알려진 한계에 적는다.
- **쓰임**: 사고 판단 문턱 −1(§3) · 위험성 +2/+3(§6) · 예방 안내 1 km 앞 1회(낮은 우선순위): "전방 1km 사고 다발 구간. 안전거리를 유지하세요." 결빙 다발은 겨울·야간·기온 조건이 맞을 때만 말한다(여름 낮에 결빙 다발을 말하면 신뢰를 잃는다).
- **공식 정보 교차 확인**: ① 각 차가 순정 내비 `NaviHelper` 의 `TrafficStatus.trafficEventList`(경로 안내 중 제공)를 받아 `ACCIDENT`·`ROAD_DAMAGE`·`DISASTER` 를 허브에 올린다(위경도 → 경로 투영 s, `startTime`·`endTime`·`description`) — 인증키·PC 없이 차 안에서 끝난다. ② PC 허브는 보조로 도로공사 문자·VMS 를 1분마다 읽는다. 사고 의심 ±2 km 에 공식 `ACCIDENT` 가 있으면 2단계 "공식 확인", 해제는 `endTime`. 순정 내비가 같은 지점을 이미 경보했으면(같은 위치·시간) 우리 안내는 한 번만. 우리 판단이 공식보다 **먼저** 나오는 시간(초 vs 분)이 차대차의 값 — 시연에서 그 시간차를 보여 준다. `onCautionPointInfo` 의 SLIPPERY_ROAD_ALERT·ROAD_DAMAGE_ALERT 는 위험성(§6) 입력으로.
- **낡음**: 다발 구역은 연 단위라 최근 연도에 가중, 3년 지난 것은 뺀다.

## 9. 한 줄로 묶기 — 다발 구역 → 위험성 → 사고 판단 → 교통 막힘 → 2차 사고 예방
지점(s)마다 허브가 **위험 맥락** `{zone, env(비·결빙·야간·터널·교량), ahead(확정 위험), incident(점수·단계·근거), official(도로공사)}` 하나를 두고 세 기능이 같이 읽고 쓴다.

```
공공데이터(다발·결빙·터널·교량)  도로공사 실시간 문자·VMS
        │ 사전 확률·예방 안내            │ 교차 확인·해제
        ▼                              ▼
사고 위험성(예측, 나에게) ──'높음'이면 문턱 −1──► 사고 판단(사후, 근거 합산) ──확정──► 교통 막힘 주의(뒷차·가족, 권장 속도)
        ▲                                   │                                   │
        └── 앞 사고 의심 +3 ───────────────────┘                                   └─ 해제(통과·보고 차 주행·공식)
                                             └──► 사고 난 차: 괜찮으세요? → 2차 사고 예방 모드 → 응급 카드·119
```
- 같은 자리 한 문장: 사고 의심(교통 막힘) > 위험 높음 > 다발 예방. 낮은 것은 화면에만.
- 문장에 맥락: "전방 2.6km **사고 다발 구간**, 사고 의심. 차량 1대 충돌 후 정차, 응답 없음 확인. **비 — 교통 막힘 주의**, 서행하세요."

## 10. 맹점·반론 (비판적으로 본 것)
1. **1 Hz 속도로는 충돌을 못 가른다** → 10 Hz 필수. 에뮬레이터가 10 Hz 를 안 주면 시연은 VC 속도 PUT(순간 변화)로 가능하지만 실차 검증 항목으로 남긴다.
2. **측면·후방 추돌 미검출**(종방향 Δv 작음) → 에어백·무응답·다른 차 확인으로만. 한계로 적는다.
3. **위조 보고**: 익명 1대 확정은 공격면 → 사람 확인(무응답)·세션 나이·속도 연속성·빈도 제한. 그래도 완전하지 않다 — 제품은 차량 인증(Pleos 계정) 필요.
4. **터널·음영 지역** 통신 끊김 → 터널 구간 데이터로 제외. 데이터 없는 도로에서는 끊김을 근거에서 뺀다.
5. **휴게소·갓길 정차** → 휴게소 500 m 제외, 급제동 없는 정차는 창이 안 열림. 급제동 뒤 갓길 휴식은 1단계(2대 필요)로 남는 보수성.
6. **알림 피로**: 위험성·예방·사고·비·정체가 겹친다 → 5분 예산, 우선순위, 같은 자리 한 문장, 주행 규제 중 축소. IVBSS 보고서도 경고 통합·우선순위가 핵심 과제였다.
7. **거짓 "사고" 단정의 책임** → "의심"·근거 읽기·공식 확인 등급 분리.
8. **위치 정확도**(속도 적분) → 실차는 내비 위치. 시연은 100 m 오차 감수.
9. **도시 도로** 신호 정차 → 지금은 고속도로만. 도시 경로가 생기면 "감속 전 60 km/h↑" 조건.
10. **개인정보**: 에어백·무응답·위치는 민감 → 그룹 안 이름, 밖은 익명·대수, 15분 뒤 삭제. 운전 습관은 차 안에서만.
11. **블루링크와 겹침**: ACN 은 센터 통보. 우리는 뒷차·가족·대피 — 역할을 문서와 화면에 분명히.
12. **데이터 낡음·커버리지**: 다발 구역은 연 단위, 고속도로 전용 목록은 확인 안 됨 → 표준데이터에서 고속도로 좌표만 걸러 쓴다.
13. **운전 습관 점수의 과학성**: 조향 기준은 개인·속도 의존(문헌) → 기준선 대비, 말은 "휴식 권장"뿐. 평가 지표로 광고하지 않는다.
14. **단일 허브**: 허브가 죽으면 링크 전체가 죽는다 → 제품은 지역별 다중 허브; 시연은 한 대.
15. **위치정보법**: 위치정보를 받아 서비스하면 **위치기반서비스사업 신고**(방통위), 개인위치정보 **동의**, 아동은 법정대리인 대리 동의(자료마다 7/8/14세 — 현행 조문 확인). 아이 휴대폰 위치를 쓰는 데리러 가기와 가족 그룹에 바로 적용된다. 익명 도로 링크는 개인을 식별하지 않도록 차 id 를 세션마다 바꾸고 15분 뒤 지운다.
16. **타당성 검사의 표준**: V2X 는 수신 메시지의 속도·위치 일관성(연속 메시지 사이 거리/속도, 속도 0 이면 위치 불변), 참가자 종류별 가능 속도를 검사하고 **한 번의 실패가 아니라 실패 패턴**으로 위조를 가른다(ETSI TR 103 460, SCMS misbehavior authority). 허브의 1대 확정 조건에 "최근 60초 보고의 위치·속도 일관성 통과"를 넣고, 실패가 쌓인 차는 그날 확정 자격을 뺀다.
17. **에어백은 에뮬레이터에 없다**: 심사 시연에서 에어백 근거는 훅으로만 보인다 — 발표에서 "실차 검증 전"이라고 말한다.
18. **메시지 길이**: 즉각 반응이 필요한 안내는 짧게, 소리 길이는 운전자 평균 반응 시간보다 짧게(IVBSS·FHWA ATIS 지침). 2단계 문장은 2문장·행동 하나로 자르고, 근거는 둘까지.
19. **교통안전이음과의 겹침**: 같은 뒷차가 카카오내비와 Tago 양쪽에서 경고를 받을 수 있다 → 순정 내비·다른 앱의 안내가 나오면(Pleos 내비 이벤트) 우리 안내를 15초 미룬다. 장기적으로 도로공사 채널에 우리 판단을 **보내는** 쪽(카카오처럼)이 자리다.
20. **순정 내비 돌발 정보의 조건**: `TrafficStatus` 는 경로 안내 중에만 오는 것으로 보인다(문서상 `RouteStateInfo.trafficStatus`). 안내 없이 달리는 차는 받지 못한다 → 그룹의 한 차만 받아도 허브가 모두에게 나눈다. 에뮬레이터 내비는 현재 위치가 성남에 고정돼 경부선 돌발이 오지 않을 수 있다 → 시연 훅 `official_sim`.
21. **2차 사고의 시간 창**: 사고 의심 15분 만료는 짧다. 문헌의 2차 사고 창은 15분~2시간·1~3 km 상류라, 정체가 남아 있는 동안 유지(최대 2시간)로 바꿨다. 반대로 정체 없이 금방 치워진 사고는 15분에 끝난다.
22. **운전자 확인 UX 의 역효과**: 충돌 뒤 운전자가 화면을 만지려 몸을 움직이는 것 자체가 위험할 수 있다 → 음성 "괜찮아"로도 끝내고, 무응답이 곧 신고가 아니라 "뒷차·가족 알림 + 119 화면 준비"임을 문장에 밝힌다. 자동 119 발신은 하지 않는다(블루링크·eCall 의 몫).

## 11. 구현 순서(제안)와 시험
1. **① 사고 판단 핵심**: 10 Hz 속도 + `IMPACT`(EDR 조건, 즉시 전송) · 점수·단계·1대 확정 조건 · 통신 끊김(터널 제외) · "괜찮으세요?" 20초 · 교통 막힘 문장·스트립 라벨 · 해제 규칙 · 대조 사례. **시연**: 앞차 VC 90→0 순간 → 20초 무응답 → 뒷차 "충돌 후 정차, 응답 없음 확인. 교통 막힘 주의".
2. **② 2차 사고 예방 모드**: 내 차 화면(비트박스·119)·가족 알림 — 응급 카드 재사용.
3. **③ 공공데이터**: 다발·결빙 다발·터널·교량 구역 → 경로 파일; 도로공사 문자·VMS 교차 확인(인증키 발급 필요).
4. **④ 사고 위험성**: 환경·도로 묶음 먼저, 운전 묶음(기준선)은 마지막.
- 시험 결과(2026-11-01, 디버그 훅 `--ez probe_signals true`): (a) PERF_VEHICLE_SPEED FASTEST = **10.2 Hz ✅**, (b) `hasSeatAirbagBeenDeployed` = **에뮬레이터 미지원 ❌**(속성 없음), (c) 도로공사·기상청 API 는 인증키 발급 뒤 명세 확인(미착수).
- 심사용 데모 순서: 앞차 VC 90 → 0(0.1초) → "괜찮으세요?" 20초 무응답 → 뒷차 "충돌 후 정차, 응답 없음 확인. 교통 막힘 주의" (3초 안) → 앞차 화면 비트박스 → (선택) 도로공사 문자 모의 → "사고 구간(도로공사 확인)".

## 11-1. 구현 명세 (4판) — 알고리즘·스키마·화면·시험

### A. 차 쪽(`RoadLinkController`·`CarSignals`)
```
도로 링크 시작  → 차속 FASTEST 구독(10 Hz), 표본 링 버퍼 20개(시각 ns, m/s)
표본마다       → 창 Δt ≤ 200 ms 에서 v_old − v_new ≥ 3.0 → '충돌 후보'(t0, s0, v_pre = 창 시작 속도)
후보 뒤 0.5 s  → 표본 5개 모두 v < 0.5·v_pre → IMPACT 확정 → 즉시 POST /api/road/event {type: IMPACT, value: "25.0→0.6", s, speed, samples:[...20]}
               → 아니면(튐) 버림
IMPACT 또는 AIRBAG → 30초 동안 1초마다 에어백 읽기(에뮬레이터는 훅) → true 면 event AIRBAG
IMPACT 또는 AIRBAG → 내 화면 "괜찮으세요?" [괜찮아요] [도움 필요] + 20초 카운트다운 + STT("괜찮아") 
               → 응답: POST /api/road/respond {me, t, ok: true|false}; 무응답 20초: {ok: null, timeout: true}
               → ok=false 또는 timeout → 2차 사고 예방 모드(§5)
급제동·급조향   → 지금 규칙 그대로(1 Hz 틱)
```
- 10 Hz 구독은 도로 링크 중에만(평소 1 Hz). CPU: 콜백당 산술 몇 번 — 주행 중 5 % 예산에 무관. 메모리: 버퍼 20개.
- 시연 훅: `--es impact_sim "25,0"`(속도 25→0 표본을 버퍼에 넣는다), `--ez airbag_sim true`, `--ez comm_sim true`(20초 보고 중단), `--ez respond_timeout true`.

### B. 허브(`link_server.py` = `LinkHub.kt`, 상수 한 표에)
```
상수: IMPACT_DV 3.0 / IMPACT_DT 0.2 / WINDOW 60 s / NEAR 300 m / STOP_HOLD 30 s / COMM_LOSS 8 s / COMM_AFTER 15 s
      RESPOND_WAIT 20 s / SCORE_MIN 3 / SCORE_STRONG 6 / CLEAR_PASS 3 / CLEAR_QUIET 120 s / TUNNEL_MARGIN 500 m
차마다 incident 창: {s0, t0, evidence: {HARD_BRAKE, SWERVE, IMPACT, STOP, AIRBAG, COMM_LOSS, NO_RESPONSE}, score, closed}
이벤트 수신(HARD_BRAKE·SWERVE·IMPACT·AIRBAG): 창이 없거나 (|s−s0| > NEAR 또는 t−t0 > WINDOW) 면 새 창, 아니면 같은 창에 근거 추가
  - IMPACT 는 samples 로 재검증(허브가 같은 식으로 Δv 계산) — 실패하면 HARD_BRAKE 로 낮춘다
상태 보고(1 Hz)에서: v < 5 km/h 가 STOP_HOLD 이어지고 창 안이면 STOP(휴게소 500 m 안이면 제외)
보기 요청 때마다(clock): 창이 있는 차가 IMPACT 를 갖고, 마지막 보고가 t0+COMM_AFTER 안이고, now − last ≥ COMM_LOSS, 터널 밖 → COMM_LOSS
respond: ok=true → 창 closed(사고 아님, 급제동만 남김) / ok=false·timeout → NO_RESPONSE
score = Σ점수(§3) (+ 다발 구역·위험 높음 보정 최대 −1 은 문턱 쪽에)
score ≥ SCORE_MIN 이고 {STOP, IMPACT, AIRBAG, COMM_LOSS} ∩ evidence ≠ ∅ → 그 차가 INCIDENT 를 보고(지금 _report 경로, 300 m 병합)
확정: 그룹 차 1대 | 모르는 차 2대 | (score ≥ SCORE_STRONG 이고 {NO_RESPONSE, AIRBAG} ∩ evidence ≠ ∅ 이고 세션 ≥ 120 s 이고 타당성 통과 이고 그 차의 최근 30분 강한 확정 0)
단계: 2 if score ≥ SCORE_STRONG or 확인 ≥ 3 or official else 1
해제: 보고 차 v > 60 km/h | 통과 ≥ CLEAR_PASS 대 60 km/h↑ 이고 CLEAR_QUIET 동안 300 m 안 정차 0 | official 해제 ; 통과 1~2대면 partial=true
타당성(차마다 최근 60 s): |Δs| ≤ v·Δt·1.5 + 50 m, v ≤ 60 m/s, 보고 간격 ≤ 5 s — 실패 3회↑ 면 그날 강한 확정 자격 없음
```
- 보기(view) 하자드 항목에 더하는 필드: `evidence: ["HARD_BRAKE","IMPACT","NO_RESPONSE"]`, `score`, `level`, `partial`, `official: {src:"ex", at, text}|null`, `label`(지금), `dangerousEndOfQueue: true`(교통 막힘 주의 = DENM 27 대응), `causeCode: 2|27`.
- 새 경로: `POST /api/road/respond`(차), `GET /api/road/official`(허브가 도로공사 API 를 읽어 캐시 — PC 서버만, 앱 허브는 시연 훅으로 주입 `POST /api/road/official/sim`).
- 대조 검사는 두 엔진에 같은 요청·같은 논리 시각 → 결과 동일(지금 방식). 도로공사 API 는 대조에서 모의값으로.

### C. 말·화면(Pleos 문법, `docs/ux-writing.md`: 한 번에 한 문장, 거리·무엇·누가 확인·행동)
- 1단계 "전방 2.6km 사고 의심 구간. 차량 2대 급제동 후 정차 확인. 교통 막힘 주의, 감속 후 차로를 확인하세요." / 2단계 "…차량 1대 충돌 후 정차, 응답 없음 확인. 교통 막힘 주의, 서행하세요." / 부분 통행 "…일부 차로 통행 중. 서행하세요." / 공식 "전방 2.6km 사고 구간(도로공사 확인). 서행하세요."
- 앞길 스트립: 핀 라벨 "사고 의심 · 교통 막힘 주의"(2단계 빨강, Safety 카드 색), 아래 작은 글(Label S 20)로 근거 칩 둘 "충돌 · 응답 없음". 헤드라인(Title 40) "2.6km 앞 사고 의심", 보조(Body 28) "아빠 차량이 알렸습니다 · 교통 막힘 주의".
- **2차 사고 예방 모드 화면**(사고 난 차): 상태 영역 전체. 헤드라인 "괜찮으세요?" + 큰 버튼 둘(Large 100: [괜찮아요] Primary, [도움 필요] Danger) + 카운트다운(Body M). 20초 뒤 또는 [도움 필요] → 응급 카드(기존 InfoCard Safety: 위치·차량·탑승 인원·시작 후 n초) + 비트박스 4줄(InfoCard Neutral, 한 줄씩 체크) + [119 전화 화면] Danger + [끝내기] Secondary. 주행 규제 무관(정차). 음성: "괜찮으세요? 괜찮으면 괜찮아요라고 말해 주세요." → 무응답 "사고 의심을 뒤차와 가족에게 알렸습니다. 비상등을 켜고 가드레일 밖으로 대피하세요."
- 소리 예산: 5분에 비상급 외 2건. 비상급 = 사고 의심 2단계·긴급차량·내 차 충돌. 순정 내비가 안내 중(NaviHelper 이벤트)이면 15초 미룸. CarUxRestrictions 켜지면 1단계·위험성 '주의'·다발 예방은 화면만.
- 휴대폰(가족 그룹·동승자 페이지): 같은 문장 한 줄 + 지도 핀, 사고 난 차의 가족에게는 "응답 없음 · 위치 · 119 연결" 카드.

## 12. 결정이 필요한 것
1. 충돌 기준을 EDR 조건(150 ms 8 km/h)으로 — 10 Hz 구독(IPC 10배, 도로 링크 중만) 수용 여부.
2. 1대 확정 조건(6점 + 무응답/에어백 + 세션 조건) — 더 보수적으로 "항상 2대"로 갈지.
3. "괜찮으세요?" 10초 + 카운트다운 20초 — 운전자에게 묻는 UX 허용 여부(주행 규제·Pleos 정책 검토 필요)와 시간.
3-1. 공식 확인을 순정 내비 `TrafficStatus`(차, 인증키 없음)로 먼저 갈지, 도로공사 API(PC)도 같이 붙일지.
4. 공공데이터 인증키 발급(도로교통공단·도로공사·기상청) — 지금 신청할지, 시연값으로 갈지.
5. 위험성 점수표(§6-2) 가중치·단계 문턱.
6. ETSI DENM 대응표를 문서에만 둘지, 메시지 필드(`causeCode`)로도 내보낼지.
